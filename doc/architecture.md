# Situation Monitor - 项目架构文档

## 一、项目概述

Situation Monitor 是一个**实时情报监控仪表盘**，用于从多个公开数据源（新闻、金融市场、加密货币、政府数据等）聚合信息，并通过智能分析引擎发现跨源关联模式、叙事趋势和关键人物。

简单来说：它就像一个"全球态势感知大屏"，把散落在互联网各处的信息集中到一个页面上，帮助用户快速了解"世界上正在发生什么"。

## 二、技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | SvelteKit 2.0 + Svelte 5 | 使用最新的 runes 语法（`$state`, `$derived`, `$effect`） |
| 语言 | TypeScript（严格模式） | 全项目类型安全 |
| 样式 | Tailwind CSS | 暗色主题 |
| 可视化 | D3.js | 交互式世界地图 |
| 测试 | Vitest + Playwright | 单元测试 + 端到端测试 |
| 部署 | Vercel（主站）+ GitHub Pages（重定向） | 纯静态站点 |

## 五、各模块详解

### 5.1 配置层 (`config/`)

**作用**：集中管理所有可配置项，让业务逻辑与配置数据分离。

这一层只包含纯数据（数组、对象），不包含任何业务逻辑。好处是：想要添加一个新的新闻源，只需在 `feeds.ts` 里加一行配置，不需要改任何其他代码。

关键配置文件：
- **`feeds.ts`**：定义了 30+ 个 RSS 新闻源，按 6 个分类（政治、科技、金融、政府、AI、情报）组织
- **`keywords.ts`**：定义了 21 个警报关键词（如 "war", "nuclear"），以及按地区和话题的关键词检测
- **`analysis.ts`**：定义了 20 个关联主题（用正则表达式匹配）和 16 个叙事模式
- **`map.ts`**：定义了地理数据（热点、冲突区、海上咽喉、军事基地、核设施等）

### 5.2 数据获取层 (`api/`)

**作用**：从外部 API 获取原始数据，转换成应用内部格式。

每个文件对应一类数据源：

| 文件 | 数据源 | 获取方式 |
|------|--------|----------|
| `news.ts` | GDELT（全球新闻） | 通过 CORS 代理 |
| `markets.ts` | Finnhub（股市）+ CoinGecko（加密货币） | 直连 + CORS 代理 |
| `fred.ts` | FRED（美联储经济数据）+ Fed RSS | 直连 + CORS 代理 |
| `leaders.ts` | GDELT（领导人新闻） | 通过 CORS 代理 |
| `misc.ts` | 无（模拟数据） | 返回硬编码数据 |

**数据获取的两个关键挑战**：
1. **跨域问题**：浏览器不允许直接请求其他域名的 API，所以需要通过 CORS 代理（Cloudflare Worker）中转
2. **速率限制**：为避免被 API 封禁，新闻获取在各分类之间加入 500ms 延迟，领导人新闻按每批 5 人、批间 300ms 延迟获取

### 5.3 服务韧性层 (`services/`)

**作用**：保护应用免受网络故障的影响。这是一个独立的基础设施层。

想象你在用一个网站，如果某个 API 挂了，正常情况下整个页面就白屏了。韧性层就是为了防止这种情况：

#### 缓存管理器 (CacheManager)
- **两级缓存**：
  - L1（内存）：速度最快，最多 100 条，页面关闭就没了
  - L2（localStorage）：稍慢，但刷新页面还在
- **过期策略**：每条数据都有 TTL（存活时间），过期后标记为"陈旧"，但在获取新数据之前仍然可用（stale-while-revalidate）

#### 熔断器 (CircuitBreaker)
- 类比家里的电闸：如果某条线路连续短路（API 连续失败），就自动断开，过一段时间再试
- 三个状态：
  - **关闭（正常）**→ 连续失败 N 次 → **打开（断开）**→ 等待超时 → **半开（试探）**→ 成功则关闭，失败则重新打开

#### 请求去重器 (RequestDeduplicator)
- 问题场景：用户连点刷新按钮，可能同时发出 5 个一样的请求
- 解决方案：如果已经有一个相同请求在进行中，新请求直接复用同一个 Promise，而不是重复发请求

#### 统一客户端 (ServiceClient)
- 把上面三个组件串联起来，对外提供统一的 `request()` 接口
- **注意**：目前实际的 API 调用还没有完全接入 ServiceClient，大部分直接使用 `fetchWithProxy()`。ServiceClient 是为未来迁移准备的基础设施

### 5.4 状态管理层 (`stores/`)

**作用**：管理应用状态，连接数据获取和 UI 显示。

Svelte 的 store 机制可以理解为"可观察的变量"——当数据变化时，所有引用它的组件自动更新。

| Store | 管理内容 | 持久化 |
|-------|----------|--------|
| `news` | 6 个分类的新闻列表、加载状态、错误 | 否 |
| `markets` | 股指、板块、大宗商品、加密货币 | 否 |
| `settings` | 面板开关、排列顺序、大小 | localStorage |
| `refresh` | 刷新状态、自动刷新配置、刷新历史 | localStorage |
| `monitors` | 用户自定义关键词监控器 | localStorage |
| `fed` | 美联储经济指标 + 新闻 | 否 |

### 5.5 分析引擎 (`analysis/`)

**作用**：对聚合的新闻数据进行智能分析，这是项目最有价值的部分。

#### 跨源关联检测 (`correlation.ts`)
- **做什么**：扫描所有新闻标题，找出多个不同来源都在报道的同一个话题
- **为什么有用**：如果 CNN、BBC、路透社同时都在说"关税"，那关税问题大概率很重要
- **输出四种信号**：
  1. **新兴模式**：某话题被提及 3 次以上
  2. **势头信号**：某话题的提及数量相比 10 分钟前在增长
  3. **跨源关联**：某话题被 3+ 个不同来源报道
  4. **预测信号**：综合评分超过阈值时，生成预测文本（如"未来 24-48 小时市场波动可能加剧"）

#### 叙事追踪 (`narrative.ts`)
- **做什么**：追踪信息从边缘媒体到主流媒体的传播路径
- **为什么有用**：很多重大新闻最初都出现在小众渠道，观察叙事的传播可以提前预警
- **来源分类**：每个新闻源被标记为"边缘"、"另类"或"主流"
- **关键输出**：当同一叙事同时出现在边缘和主流媒体时，标记为"叙事穿越"

#### 主角分析 (`main-character.ts`)
- **做什么**：统计 20 位公众人物被新闻提及的次数，找出"今日主角"
- **支配度计算**：衡量第 1 名领先第 2 名多少（0-100 分）

### 5.6 UI 层 (`components/`)

**作用**：将数据呈现给用户。

#### 布局结构
```
+layout.svelte（暗色背景壳）
  └── +page.svelte（主页面，所有逻辑入口）
        ├── Header（顶部导航，刷新状态）
        ├── Dashboard（多列瀑布流网格）
        │   ├── MapPanel（D3 世界地图）
        │   ├── NewsPanel ×5（五个新闻分类）
        │   ├── MarketsPanel（股市指数）
        │   ├── HeatmapPanel（板块热力图）
        │   ├── CryptoPanel（加密货币）
        │   ├── CorrelationPanel（关联分析）
        │   ├── NarrativePanel（叙事追踪）
        │   ├── MainCharPanel（主角分析）
        │   ├── ... 更多面板
        │   └── MonitorsPanel（自定义监控）
        ├── SettingsModal（设置弹窗）
        ├── MonitorFormModal（监控器编辑弹窗）
        └── OnboardingModal（首次使用引导）
```

#### 响应式布局
Dashboard 使用 CSS `column-count` 实现响应式多列布局：
- < 600px：1 列（手机）
- 600px+：2 列
- 900px+：3 列
- 1200px+：4 列
- 1600px+：5 列
- 2000px+：6 列（大屏）

#### 面板系统
所有 19 个面板都使用统一的 `Panel.svelte` 包装器，提供：
- 标题栏（标题、计数、状态指示器）
- 加载中旋转器
- 错误显示
- 折叠/展开功能

用户可以通过设置面板控制每个面板的显示/隐藏，也可以使用预设快速切换面板组合。

## 六、数据流总结

```
1. 页面加载 → onMount() 触发初始加载
2. 并行调用所有数据获取函数
3. 各 API 模块从外部获取数据（通过 CORS 代理）
4. 数据写入对应的 Store
5. Store 变化触发 UI 自动更新
6. 分析引擎在 UI 层运行（以 allNewsItems 为输入）
7. 分析结果传递给对应的分析面板
8. 自动刷新定时器每小时重复步骤 2-7
```
